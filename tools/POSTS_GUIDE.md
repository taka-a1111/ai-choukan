# 投稿下書きの書き方と投稿の手順（note・X・Facebook） ver3.3 (2026-11-23)

AIトレンド朝刊の号から、インフォサクセス名義の投稿の下書きを作り、投稿するときの決まり。

高崎さんの決定（2026-11-17。インフォサクセスの note を収益化するため）
- note は毎日の投稿をやめ、週1回・日曜の朝に「今週、小さな会社がやること」のまとめ（週1まとめ）を無料で出す。その週の号から、小さな会社に関係のある話題を5本ほど選ぶ
- 週1まとめの最後には、インフォサクセスの有料note（5,000円の「AI検索30分チェックリスト」と、29,800円の手順キット）への案内を必ず入れる。ただし有料noteの公開前（data/promo.json の url が空のうち）は入れない
- X は毎日3本（朝・昼 12:15・夜 20:00）を続ける。月〜土の朝の1本は、最新の週1まとめのURLを付ける（まだ無ければURLなし）
- 2026-11-11〜11-15 に公開した毎日の note 5本は消さずに残す。有料noteを公開したら、最後に案内を1行ずつ足す（7-7）

下書きはアプリの「投稿」タブに出る（毎朝5:27の予約実行が作る）。毎朝6:43の予約実行「AI朝刊の自動投稿」が、その日の下書きを投稿する（第8章）。
自動で出なかった日は、高崎さんがアプリの「Claudeに投稿を頼む」を押し、開いたプロジェクト「AI朝刊」のチャットに依頼文を貼り付けて送ると、Claude が投稿する（第7章）。
自動投稿の予約実行と高崎さんの依頼の、どちらでもない投稿はしない。

| 曜日 | 下書き（kind） | 投稿するもの |
|---|---|---|
| 月〜土 | daily（note なし） | X の朝の1本（最新の週1まとめのURLつき。無ければURLなし）・昼 12:15・夜 20:00 |
| 日 | weekly | note の週1まとめ、X の朝の1本（週1まとめの紹介＋そのURL）・昼 12:15・夜 20:00、Facebook ページで週1まとめを紹介 |

## 1. だれに向けて書くか

- 読者：Web担当者、小さな会社の経営者、フリーランス
- 扱う話：SEO・AI検索、集客、サイト制作、業務の自動化、AIの導入に効く話だけ
- 書き手：インフォサクセス（SEO・Web制作・自動化・AI導入の支援をしている立場）
- ねらい：ニュースを並べるのではなく、「で、何をすればいいか」まで書く

## 2. 話題の選び方

高崎さんの方針（2026-11-13）：注目度が高いニュースを優先して選ぶ。注目度は、まず python3 tools/rank_topics.py --date D --repo <リポジトリ> で一覧にして決める（媒体数・記事数・国内と海外の両方で報じられたか・動画でも扱われたか・重要度・主要な企業やサービスか・続報か、から出した目安。SNS の数字ではない）。

高崎さんの方針（2026-11-13、追加）：AIの新しいモデル・新しいバージョン・新しいツールや機能の話題を優先する。rank_topics.py はこれらに加点し（＋6、主要な企業・サービスの版の番号つきならさらに＋2）、一覧の「新しさ」の列に「新」と出す。新モデルの話題も読者向け○として扱う。

- 今日の1本（main）：読者向け（一覧の「読者向け」が○）の話題のうち、注目度が一番高いもの
  - 注目度が並んだら（差が3以内）、「業務に効く」の印（biz）があり、読者が自分で手を動かせる方を選ぶ
  - 新しいモデル・バージョン・ツールの話題を優先する（加点済み）。書くときは「日本で使えるか・いつから・料金・小さな会社に何が変わるか」を中心にする。性能の数字の比べ合いだけで終わらせない
  - 前の日の main と同じ出来事は選ばない（data/posts/ の直近3日分を見る）。続報は、新しい事実で読者のやることが変わるときだけ
- ほか3本（others）：注目度の高い順に3つ
  - その日いちばん注目度の高い話題が「読者向け×」（株価・人事・政治など）でも、main との差が大きければ1つ目に入れてよい（「今日いちばん話題になったニュース」として。読者の仕事への影響が小さいときは、そう書く。号の解説にない影響を作らない）
  - 残りは読者向け○から、新しいモデル・ツールを優先しつつ、main と同じ分野に寄せず散らす
- X の昼の1本（x_topics）：main・others に入れない話題のうち、読者向け○で注目度が一番高いもの
- 読者向け○の話題が1つもない日は、活用ノウハウや国内の事例から選ぶ。それも無ければ下書きを作らず、報告に書く
- 報告には、main と others の注目度の数字を添える
- main・others は X の朝の1本と今日の3つで使う（月〜土は note が無い）

### 2-2. 週1まとめの5本（日曜だけ）
- その週の号（日曜 D の6日前の月曜〜D）の全部で、python3 tools/rank_topics.py --date <各日> --repo <リポジトリ> を実行し、読者向け○の話題を注目度の高い順に並べる
- 「小さな会社に関係のある話題」を5本（4〜6本）選ぶ。小さな会社が自分で手を動かせる・費用や手間が変わる・集客や検索に効く・安全のために確かめることがある、のどれかに当たるもの。新しいモデル・ツールを優先する（注目度に加点済み）
- 同じ出来事が週に何度も出ていたら1本にまとめ、いちばん新しい事実のある日の号の話題を選ぶ（続報の前の号の話題を合わせて week_topics に入れてもよいが、本数に数えるのは1本）
- 分野が1つに寄らないよう散らす（SEO・検索、ツール、開発・自動化、安全、活用ノウハウ など）
- 報告に、5本の見出しと注目度を添える

## 3. 週1まとめ（note）の型（日曜だけ）

タイトル：「今週、小さな会社がやること5つ」で始め、その週の中身が分かる言葉を足す（例「今週、小さな会社がやること5つ：Gemini 4の新料金、サイトの更新…」）。60字まで。あおらない（「衝撃」「ヤバい」「知らないと損」などは使わない）

本文（見出しは行頭に ## 、話題ごとの小見出しは ### 。この順番で書く）

1. ## 30秒まとめ　3行の箇条書き（「・」で始める）。今週いちばん大事なこと、今週やることの柱、日本で使えるかの要点
2. ## 今週の5本　話題ごとに「### 1. 見出し」の小見出しを立て、その下に次の4つを段落で書く（空行で区切る）
   - 何が起きたか（2〜3文。号の解説をもとに、やさしい言葉で）
   - 「いつ・誰が使える：」で始まる1〜2文（号の avail のとおり。分からないことは「発表されていません」）
   - 「小さな会社への影響（私の見立て）：」で始まる1〜2文（言い切らない）
   - 「やること：」で始まる1文（今週できる具体的な作業）
3. ## 今週やること5つ　番号つきで、各話題の「やること」を1行ずつ（「1. 」で始める）。1つは道具なしでできること（いまの状態を記録する など）を入れる
4. ## 30秒セルフチェック　形は前と同じ
   - 1行目「当てはまるものを数えてください。」
   - 「・」で始まる3行（今週の5本に関係する、自分で確かめられる状態）
   - 結果を3行（空行をはさまない）：「当てはまるのが0個：…」「1〜2個：…」「3個：…」。「今週やること5つ」のどれから手をつけるかにつなげる
   - 空行をはさんで、毎回同じ2行
     「サイトそのものの更新や設定（WordPressのプラグインやPHPの版など）は、URLを入れるだけの無料チェックで確かめられます。」
     https://sukizero.com/
5. ## 出典　5本の出典のURLを、1行に1つ。前後に文字を付けない
6. ## もっと手を動かしたい方へ　有料noteの案内。data/promo.json の paid_notes のうち url が入っているものを、その line の文の次の行に url を置いて並べる（文言を変えない。URLは1行に単独）。url が空で pending_line があるもの（準備中の手順キット）は、その1文をそのまま最後に置く（予告。URLは付けない）。url も pending_line も無いものは書かない。tools/build_posts.py が、どちらも本文にあるかを検査する
   - いまの状態（2026-11-18）：5,000円の「30分チェックリスト」は公開済み（url あり）。手順キットは infosuccess.jp での実例がそろってから 30,000円で公開し、のちに39,800円に上げる予定（有料noteの案件の決定）。それまでは予告の1文だけを入れる
7. 最後に相談窓口への1文と、インフォサクセスのサイトのURL（毎回同じ。空行をはさみ、URLは1行に単独で置く）
   「AIを仕事にどう入れるか、検索やAIからの集客をどう整えるかのご相談は、インフォサクセスのサイトからどうぞ。」
   https://infosuccess.jp/

長さ：2500〜5500字（tools/build_posts.py が数える）

画像（ChatGPT で作る。指示の書き方は第4-2章）
- 見出し画像：記事の顔。X の日曜の朝の1本にも付ける
- 図解2枚：「## 今週の5本」の下（5本の一覧）と「## 今週やること5つ」の下（5つの作業を番号つき）に1枚ずつ

月〜土は note を書かない（posts.json に note を入れると build_posts.py が止める）。

## 4. X の型

- 毎日3本作る（朝・昼・夜に1本ずつ）。x の並びはこの順、at も書く。昼の1本はリンクなし（X はリンクつきの投稿を表示しにくくする傾向があり、リンクなしで役に立つ投稿がフォローにつながるため）
  - 朝の1本（"at":"朝"）
    - 月〜土：main を3つの箇条書きで。その投稿だけで分かる形にし、note の話は書かない（その日の note は無い）。投稿のときに Claude が、最新の週1まとめのURLを末尾に足す（tools/latest_weekly.py。まだ無ければ足さない）
    - 日曜：週1まとめの紹介。「今週、小さな会社がやること5つをnoteにまとめました。」で始め、5つの中から3つを箇条書きで。投稿のときに Claude がその日の週1まとめのURLを足す
  - 昼の1本（"at":"12:15"）：x_topics の話題を、その投稿だけで役に立つ形で書く（何が起きたか＋読者は何をすればよいか）。note への誘導もURLも入れない。読者に効く話題がほかに無い日は others から1つ選ぶ（x_topics は省く）
  - 今日の3つ（"at":"20:00"）：「今日のAIニュース、Web担当者向けに3つだけ。」で始め、main と others から3つを番号つきで。note への誘導もURLも入れない（毎日同じURLを2回出さないため）
- 全角140字まで（tools/build_posts.py が数える）。朝の1本はURLを足しても収まるよう、全角125字ほどまでにする
- 月〜土の3本に「note」の文字を入れない（build_posts.py が止める）
- ハッシュタグは付けない。絵文字は使わない
- 宣伝に見える書き方をしない。3本とも、読んだ人がその場で1つ得をする内容にする

### 4-2. 画像の指示（images）

posts.json の images に、ChatGPT に送る画像の文言と構成を書く（形は tools/img_prompt.py の先頭）。色・書体・禁止事項などの共通の決まりは tools/img_prompt.py が付けるので、ここには書かない。
- eyecatch（見出し画像）：主見出しは2行（head1・head2。1行12字まで）、blue は主見出しの中の青にする語、sub はサブコピー（20字まで）、labels は右の図の言葉3〜5個（1つ12字まで）、struct は右の図の構成（例「上に◯◯の箱、下向きの矢印で3つの箱に分かれる」）
- 画像の枚数：月〜土は eyecatch（X の朝の1本に付ける）と xfig の2枚。日曜は eyecatch・figs 2枚・xfig の4枚
- eyecatch の文言は、月〜土は main の話題、日曜は週1まとめの中身にする
- figs（日曜の週1まとめの図解2枚。月〜土は書かない）：fig1 は after を「## 今週の5本」にして、5本を一覧にする（縦に5つの箱）。fig2 は after を「## 今週やること5つ」にして、5つの作業を番号つきで並べる。title（12字まで）、texts（図の中の言葉。1項目1行、見出しは12字まで・説明は20字まで）、note（図の下の補足1行。図が示す結論、24字まで）、struct（構成）、alt（図が示す内容を1文で）。note の図は縦長で作り、文字を大きくする（スマホでは横幅に合わせて縮むため。横長の図は文字が小さくて読めなかった）
- xfig（X の昼の1本に付ける図）：昼の1本の話題を図にする。形は figs と同じ（after は不要）
- 図に入れる言葉は、本文と同じく号の解説にある事実だけ（tools/build_posts.py が数字を検査する）。図のためだけに数字を作らない
- 人物のアイコンを頼まない。実在の企業のロゴを描かせない（共通の決まりに入っている）
- 構成の型：手順は番号つきの縦の箱＋下向きの矢印／並列は同じ幅の横長の箱を積む／対比は2列／時間の流れは横のタイムライン。横に4つ以上並べない（スマホで潰れる）

## 5. 事実の扱い（必ず守る）

- 書いてよい事実は、その日の号の、選んだ話題の解説（lead・points・avail・why・図解・出典の要約）にあることだけ
- 数字・固有名詞・日付を足さない。号にない出典のURLを書かない
- 分からないことを分かったように書かない
- 「私の見立て」と「今日やること」は書き手の考えなので、事実のように言い切らない（「〜と見ています」「〜しておくと安心です」）
- 出典の文をそのまま写さない。自分の言葉で書く
- 取引先の名前や案件の話を入れない
- 太字記号（**）を使わない

## 6. 作る手順

日曜に週1まとめを出せなかったとき（号が出ていない・下書きが作れない・投稿が止まった）は、次の日（月曜）の下書きを週1まとめ（kind weekly）として作り、build_posts.py に --makeup を付けて書き込む。週は D の6日前〜D。投稿も日曜と同じ手順で行う（note・X・Facebook）。次の日曜の週1まとめでは、この週1まとめで扱った話題を繰り返さない（2026-11-23 に初めて行った）

1. その日の号（data/issues/D.json）があるかを確かめる。無ければ作らずに知らせる
2. data/posts/ の直近3日分を見て、同じ話題を続けて選ばないようにする
3. 話題を選ぶ（第2章。日曜は 2-2 の5本も）
4. posts.json を書く（形は tools/build_posts.py の先頭）。月〜土は kind を "daily" にして note・figs を書かない。日曜は kind を "weekly" にし、week_topics・note・figs を書く
5. python3 tools/build_posts.py --posts posts.json --date D --repo <リポジトリ>
   - NG が出たら直してやり直す。数字の NG は、号の解説を読み直して、無い数字なら消す
   - 試すだけのときは --dry-run（書き込まない）。日曜以外に週1まとめの形を試すときは --any-day
6. git add data/posts → コミット「投稿下書き D」→ push（--force はしない）
7. 約90秒後に https://ai-choukan.vercel.app/data/posts/D.json が読めるかを確かめる
8. 報告：main の見出し、others の見出し、昼の1本の話題、X の本数、画像の枚数。日曜は週1まとめのタイトル・字数・5本の見出し・有料noteの案内を入れたか

## 7. 投稿の手順（高崎さんから「AI朝刊の投稿をお願いします（D号）」と来たとき）

依頼文が、その日の投稿への了承になる。了承は D 号の下書きの分だけ。別の日の分や、下書きにない内容は投稿しない。
月〜土は X だけ（7-3）。日曜は note の週1まとめ（7-2）→ X（7-3）→ Facebook（7-3b）の順。
入力はすべて Claude が行う。高崎さんにコピーや貼り付けを頼まない。

### 7-0. 準備
- ブラウザは Claude in Chrome（CIC）を使う。スキル chrome-browser・note-editor-ops・cic-login-handoff を読む
- リポジトリを add_repo（owner taka-a1111、repo ai-choukan、access push）で取り、data/posts/D.json を読む。posted に note_url があれば投稿済みなので、二重に投稿せず、そう伝える
- アカウントを確かめる。note は https://note.com/api/v2/current_user の urlname が infosuccess_jp（日曜だけ。同じ Chrome で別名義の note「ひとり受託ラボ」なども使うため、別のアカウントになっていることがある）。違えば何も入力せず、cic-login-handoff の形で切り替えを頼む（note は同時に1つしかログインできない）
- X は左下の表示が @infosuccess_jp か。同じ Chrome でナンパ部（@nampabu）なども使うため、別のアカウントになっていることが多い。左下 [data-testid="SideNav_AccountSwitcher_Button"] を押し、出てきた一覧の @infosuccess_jp を押して切り替える（パスワードは要らない）。一覧に @infosuccess_jp が無いときは何も入力せず、cic-login-handoff の形で頼む。投稿が終わったら、元のアカウントに切り替えて戻す
- PC・Chrome につながらないときは、入力せずに「PCのChromeを開いてから、もう一度送ってください」と伝える

### 7-1. 直したい点があるとき
依頼文に「直したい点」があれば、先に posts.json を直して tools/build_posts.py で組み立て直し、push する（第6章）。事実を足す直しは、号の解説にあるものだけ。直した文面を高崎さんに見せ、「これで投稿します」と伝えてから先へ進む（返事は待たなくてよい。直しの中身が依頼とずれそうなときだけ確かめる）。

### 7-2. note（日曜の週1まとめだけ）
1. python3 tools/note_html.py --date D --repo <リポジトリ> --out note_payload.json で、タイトルと本文のHTMLを作る
2. 同じタイトルの下書きがすでにあれば（https://note.com/api/v2/creators/infosuccess_jp/contents?kind=note や下書き一覧で確かめる）、新しく作らずにそれを開く。無ければ https://note.com/notes/new を開く
3. タイトルは textarea（記事タイトル）に value の setter と input イベントで入れる。本文は .ProseMirror の全体を選択し、text/html の paste イベントで入れる（note-editor-ops 第4章）
4. 入れたあと、.ProseMirror の子要素の並び（H2,UL,P…）が note_payload.json の blocks と同じかを確かめる
5. 画像：7-6 のとおり ChatGPT で作って入れる（見出し画像、「## 今週の5本」の下の図、「## 今週やること5つ」の下の図）。本文を入れ終えてから行う
6. 「下書き保存」→「公開に進む」。ハッシュタグは「AI」「AIニュース」「中小企業」と、話題に合うものを1〜2個（例：ChatGPT、SEO）。記事タイプは無料
7. 「投稿する」を押す。安全機能で押せないときだけ、cic-login-handoff の形で高崎さんに押してもらう
8. 公開ページ https://note.com/infosuccess_jp/n/（key）を開き、タイトル・見出し・出典のリンクが出ているかを確かめる

### 7-3. X
1. 朝の1本：URLを足してから、https://x.com/compose/post で本文を text/plain の paste で入れ、見出し画像を添付して（7-6）、すぐ投稿する（note-editor-ops 第8章）
   - 月〜土：python3 tools/latest_weekly.py --date D --repo <リポジトリ> の1行目（最新の週1まとめのURL）を、改行して末尾に足す。何も出なければ（週1まとめがまだ無い）URLなしで出す
   - 日曜：その日に公開した週1まとめのURLを、改行して末尾に足す

### 7-6. 画像（ChatGPT で作り、クリップボードで渡す）

画像のデータは、ダウンロードフォルダもコンテナも通さない。ChatGPT のタブでクリップボードに写し、note・X のタブで本物の ctrl+v で受け取る（Claude の会話に画像のデータが入らない）。補助関数は tools/browser_helpers.js（ページを開くたびに、該当部分を javascript_tool で実行して定義する）。

作る順番と間隔
- 生成はスキル chatgpt-image-pacing に従う（共有ログ imggen_log に run_chatgpt_ai-choukan_D-eyecatch のように記録、いまの間隔、他の会話との順番、制限が出たら止まる）。最初の1枚の前に、ログで間隔と制限を確かめる
- 月〜土は2枚（eyecatch → xfig）、日曜は4枚（eyecatch → fig1 → fig2 → xfig）。1枚ごとに https://chatgpt.com/ を開き直して新しいチャットで送る（通常の「Chat」モード。__mode() が true）
- 指示文は python3 tools/img_prompt.py --date D --repo <リポジトリ> --which <eyecatch|fig1|fig2|xfig> --json で作り、__send(指示文) で送る（'SENT' 以外なら送らずに止める）

1枚の流れ
1. ChatGPT：__state() を30秒ごとに見て、n が1以上かつ stop が false になるまで待つ（最大5分。__bad() に何か出たら制限として扱う）
2. 仕上がりを1回だけ見る：最後の画像を scrollIntoView してスクリーンショット（小さいときは zoom で拡大）。文言が指示文と1字ずつ合っているか、文字が帯や箱からはみ出したり重なって欠けたりしていないか、余計な文字・数字・人物・ロゴ・ほかの色が無いか、見出し画像の左下が空いているか。直すときは作り直さず「この画像をベースに、下記だけ修正してください」と直す箇所だけ頼む（1枚につき1回まで。直しも1回の生成として数える）。2回目もだめなら、その画像は使わない
3. ChatGPT のタブで __copy()（'COPIED' が返ること）
4. 受け取るタブ（日曜は note のタブ、月〜土は X の投稿画面のタブ）：TARGET 部分を定義し、__sinkOn() → computer の key "ctrl+v" → __sinkGet() → __fit(window.__got, 幅, 高さ, ファイル名)
   - 見出し画像は 1280×670、note の本文の図（fig1・fig2）は 1080×1620（縦長）、X の図（xfig）は 1200×800
   - note の本文の図は、スマホの幅（390px）に縮めたときに一番小さい文字が16px以上あるかを見る（画像の横幅の5%以上）。小さければ使わずに作り直しを頼む
   - 見出し画像は、続けて __brand(ファイル) で左下に本物のロゴマークと「インフォサクセス」を描き足す（ChatGPT には社名もロゴも描かせず、左下を空けさせている）
5. note の見出し画像：エディタ上の画像ボタン →「画像をアップロード」を押す前に __capture()、押したら __setFile(null, ファイル) → 切り抜きの画面で「保存」
6. note の本文の図：__placeAfter(図の after から「## 」を除いた見出しの文字。例 '今週の5本'・'今週やること5つ'。完全に一致させる)で見出しの直後に空の段落を作ってカーソルを置き、__capture() → button[aria-label="メニューを開く"] →「画像」→ __setFile(null, ファイル)。入ったら __dropEmptyBefore(同じ見出しの文字)で見出しと図の間の空の段落を消す（補助関数は tools/browser_helpers.js の TARGET 部分。__placeAfter・__dropEmptyBefore も同じファイル）
7. X：投稿画面の入力欄 [data-testid="tweetTextarea_0"] にフォーカスして、本物の ctrl+v を押すと画像が添付される。[data-testid="attachments"] が出たことを確かめる
   - 朝の1本の見出し画像は、ロゴ入りのものを付ける。日曜は note のタブで __toClip(ロゴ入りのファイル) をしてから、X のタブで ctrl+v する。月〜土は X の投稿画面のタブで __fit → __brand したファイルを、__setFile(document.querySelector('input[data-testid="fileInput"]'), ファイル) で添付する
   - 昼の1本の図（xfig）は、ChatGPT のタブで __copy() したものをそのまま ctrl+v でよい
8. ログを done_ にする

うまくいかないとき（投稿は止めない）
- 見出し画像が作れない：日曜の note は、PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers python3 tools/note_eyecatch.py --date D --repo <リポジトリ> --out eyecatch_D.png で作った紺色の画像を、/mnt/user-data/uploads/ に写して file_upload で入れる。X の朝の1本は画像なしで出す
- 図解が作れない：その図は入れずに進める（本文は図が無くても読める）。xfig が作れなければ、昼の1本は画像なしで予約する
- 制限（Too many requests など）が出た：chatgpt-image-pacing のとおり limit_ を作り、残りの画像は作らずに、画像なしで投稿を続ける
- クリップボードに写せない（COPY_NG）：ChatGPT のタブを computer の screenshot で前面に出してから、もう1回だけ __copy()。だめならその画像は使わない
- 報告に、作れなかった画像と理由を書く

## 8. 自動投稿（毎朝の予約実行「AI朝刊の自動投稿」）

予約実行は 6:43 に動き、PC の Chrome につながらなかった日などのために 9:43・12:43・17:43 にも動く（2026-11-18〜。投稿済みなら何もせず終わるので、二重には出ない）。

高崎さんの決定：2026-11-11 に毎日の自動投稿、2026-11-12 に X を朝・昼 12:15・夜 20:00 の3本、2026-11-17 に note を日曜の週1まとめだけにした（月〜土は X だけ、Facebook は日曜だけ）。予約実行そのものが、その日の投稿への了承になる。本人は見ていないので質問しない。

### 8-1. 投稿する前に確かめること（1つでも外れたら投稿しない）
- 日付 D は TZ=Asia/Tokyo date +%F で取る。日曜かどうかは TZ=Asia/Tokyo date +%u が 7 か
- data/posts/D.json が無い：下書きが出ていない。投稿せず、通知して終わる
- posted.x_urls がある（日曜は posted.note_url もある）：投稿済み。何もせず終わる。日曜で note_url だけがあって x_urls が無いときは、X と Facebook だけを続ける
- "hold": true がある：高崎さんが止めた日。投稿せず、通知して終わる
- 共有ログ imggen_log に、作成から60分以内の run_chatgpt_ai-choukan_D- や done_chatgpt_ai-choukan_D- があれば、別の実行が今日の分を進めている。二重に投稿しないよう、何もせず通知して終わる
- PC の Chrome（Claude in Chrome）につながらない：投稿せず、「AI朝刊の投稿：PCのChromeにつながらず投稿できませんでした。アプリのボタンから頼めば出せます」と通知して終わる
- 日曜だけ：note のアカウントが infosuccess_jp でない：note は何も入力せず通知する（X は続けてよいが、朝の1本は週1まとめのURLなしで出す）
- X は 7-0 のとおり @infosuccess_jp に切り替えてから進み、終わったら元に戻す

### 8-2. 投稿
- 月〜土（kind が daily、または古い形の下書き）
  1. X：7-3 のとおり（朝の1本はロゴ入りの見出し画像と最新の週1まとめのURLつきですぐ投稿、昼の1本は図つきで 12:15、今日の3つは 20:00 の予約投稿）。画像は2枚（7-6）
  2. 記録：mark_posted.py --x-url と --x-scheduled（7-4）。コミットは「投稿済み D」
  3. 報告：SendUserMessage で X の朝の1本のURL、付けた週1まとめのURL（無ければ「なし」）、予約の時刻。PushNotification は一行「AI朝刊の投稿：X に出しました（昼 12:15・夜 20:00 は予約済み）」

### 8-3. 止める・直す（高崎さんから、投稿の前に連絡が来たとき）

### 8-4. 途中で止まったとき
7-5 と同じ。投稿できた分は必ず記録し、どこまで終わったかと理由を SendUserMessage と PushNotification で知らせる。安全機能で公開のボタンが押せないときは、下書き保存までで止め、そう知らせる（アプリのボタンから頼めば続きができる）。
