# 投稿下書きの書き方と投稿の手順（note・X） ver1.8 (2026-11-12)

AIトレンド朝刊のその日の号から、note と X の下書きを作るときの決まり。
下書きはアプリの「投稿」タブに出る。毎朝の予約実行「AI朝刊の自動投稿（note・X）」が、その日の下書きを note と X に投稿する（第8章）。
自動で出なかった日は、高崎さんがアプリの「Claudeに投稿を頼む」を押し、開いたプロジェクト「AI朝刊」のチャットに依頼文を貼り付けて送ると、Claude が投稿する（第7章）。
自動投稿の予約実行と高崎さんの依頼の、どちらでもない投稿はしない。

## 1. だれに向けて書くか

- 読者：Web担当者、小さな会社の経営者、フリーランス
- 扱う話：SEO・AI検索、集客、サイト制作、業務の自動化、AIの導入に効く話だけ
- 書き手：インフォサクセス（SEO・Web制作・自動化・AI導入の支援をしている立場）
- ねらい：ニュースを並べるのではなく、「で、何をすればいいか」まで書く

## 2. 話題の選び方

- 今日の1本（main）：読者の仕事に一番効く話題を1つ
  - 「業務に効く」の印（biz）があり、重要度が高く、読者が自分で手を動かせるものを優先する
  - 新モデルの性能比較、企業の買収・株価、研究の話は、読者の行動が変わらないかぎり選ばない
  - 前の日の main と同じ出来事は選ばない（data/posts/ の直近3日分を見る）。続報は、読者のやることが変わるときだけ
- ほか3本（others）：読者に関係のある話題を3つ。main と似た話に寄せず、分野を散らす
- 読者に効く話題が1つもない日は、活用ノウハウや国内の事例から選ぶ。それも無ければ下書きを作らず、報告に書く

## 3. note の型

タイトル：何が起きたか＋読者に何の関係があるか。60字まで。あおらない（「衝撃」「ヤバい」「知らないと損」などは使わない）

本文（見出しは行頭に ## 。この順番で書く）

1. ## 30秒まとめ　3行の箇条書き。3行目は「日本で使えるか・いつからか」
2. ## 概要　号の解説をもとに、やさしい言葉で。図解がある話題は、その中身を箇条書きにする（note は表が使えない）
3. ## いつ・誰が使える？　号の avail のとおり。分からないことは「発表されていません」と書く
4. ## 小さな会社への影響（私の見立て）　事実ではなく見立てだと分かる書き方で、2〜4文
5. ## 今日やること3つ　番号つき。今日できる具体的な作業。1つは「いまの状態を記録する」など、道具なしでできること
6. ## 30秒セルフチェック　読者が自分の状況を確かめる、文字だけの診断（note では動く仕掛けは置けない）。形は次のとおり
   - 1行目「当てはまるものを数えてください。」
   - 「・」で始まる3行。今日の1本に関係する、自分で確かめられる状態（例「ChatGPTで自社のことを調べたことがない」）
   - 結果を3行（1行ずつ改行、空行をはさまない）：「当てはまるのが0個：…」「1〜2個：…」「3個：…」。結果は「今日やること3つ」のどれから手をつけるかにつなげる
   - 最後に、空行をはさんで次の2つ（毎回同じ。URLは1行に単独で置く）
     「サイトそのものの更新や設定（WordPressのプラグインやPHPの版など）は、URLを入れるだけの無料チェックで確かめられます。」
     https://sukizero.com/
7. ## ほかに押さえておきたい3本　各2〜3文。見出し1行＋何が起きたか＋読者への意味
8. ## 出典　main と others の出典のURLを、1行に1つ。前後に文字を付けない
9. 最後に相談窓口への1文と、インフォサクセスのサイトのURL（毎回同じ。空行をはさみ、URLは1行に単独で置く）
   「AIを仕事にどう入れるか、検索やAIからの集客をどう整えるかのご相談は、インフォサクセスのサイトからどうぞ。」
   https://infosuccess.jp/

長さ：1400〜2600字

画像（ChatGPT で作る。指示の書き方は第4-2章）
- 見出し画像：記事の顔。X の朝の1本にも付ける
- 図解2枚：「## 概要」の下と「## 今日やること3つ」の下に1枚ずつ

## 4. X の型

- 3本作る（朝1本・夜2本）。x の並びはこの順、at も書く
  - 朝の1本（"at":"朝"）：main を3つの箇条書きで。最後に「くわしくは note に」の1文（URLは入れない。投稿のときに Claude が note のURLを足す）
  - 夜の1本（"at":"19:00"）：note に載せていない話題を1つ選び、その投稿だけで役に立つ形で書く（何が起きたか＋読者は何をすればよいか）。note への誘導もURLも入れない。話題IDを x_topics に入れる。読者に効く話題がほかに無い日は others から1つ選ぶ（x_topics は省く）
  - 今日の3つ（"at":"21:00"）：「今日のAIニュース、Web担当者向けに3つだけ。」で始め、main と others から3つを番号つきで。投稿のときに Claude が note のURLを足す
- 夜の1本の話題の選び方は第2章と同じ（読者の仕事に効く、読者が手を動かせる）。main・others と同じ出来事は選ばない
- 全角140字まで（tools/build_posts.py が数える。note のURLを足す2本は、足したあとも収まる長さにする）
- ハッシュタグは付けない。絵文字は使わない
- 宣伝に見える書き方をしない。3本とも、読んだ人がその場で1つ得をする内容にする

### 4-2. 画像の指示（images）

posts.json の images に、ChatGPT に送る画像の文言と構成を書く（形は tools/img_prompt.py の先頭）。色・書体・禁止事項などの共通の決まりは tools/img_prompt.py が付けるので、ここには書かない。
- eyecatch（見出し画像）：主見出しは2行（head1・head2。1行12字まで）、blue は主見出しの中の青にする語、sub はサブコピー（20字まで）、labels は右の図の言葉3〜5個（1つ12字まで）、struct は右の図の構成（例「上に◯◯の箱、下向きの矢印で3つの箱に分かれる」）
- figs（note の図解2枚）：fig1 は after を「## 概要」にして、今日の1本の中身（何ができるか・何が変わるか）を図にする。fig2 は after を「## 今日やること3つ」にして、3つの作業を番号つきで並べる。title（20字まで）、texts（図の中の言葉。1項目1行、説明は30字まで）、note（図の下の補足1行。図が示す結論）、struct（構成）、alt（図が示す内容を1文で）
- xfig（X の夜の1本に付ける図）：夜の1本の話題を図にする。形は figs と同じ（after は不要）
- 図に入れる言葉は、本文と同じく号の解説にある事実だけ（tools/build_posts.py が数字を検査する）。図のためだけに数字を作らない
- 人物のアイコンを頼まない。実在の企業のロゴを描かせない（共通の決まりに入っている）
- 構成の型：手順は番号つきの縦の箱＋下向きの矢印／並列は同じ幅の横長の箱を積む／対比は2列／時間の流れは横のタイムライン。横に4つ以上並べない（スマホで潰れる）

## 5. 事実の扱い（必ず守る）

- 書いてよい事実は、その日の号の、選んだ話題の解説（lead・points・avail・why・図解・出典の要約）にあることだけ
- 数字・固有名詞・日付を足さない。号にない出典のURLを書かない
- 分からないことを分かったように書かない
- 「私の見立て」と「今日やること」は書き手の考えなので、事実のように言い切らない（「〜と見ています」「〜しておくと安心です」）
- 出典の文をそのまま写さない。自分の言葉で書く
- 取引先の名前や案件の話を入れない
- 太字記号（**）を使わない

## 6. 作る手順

1. その日の号（data/issues/D.json）があるかを確かめる。無ければ作らずに知らせる
2. data/posts/ の直近3日分を見て、同じ話題を続けて選ばないようにする
3. 話題を選び、posts.json を書く（形は tools/build_posts.py の先頭）
4. python3 tools/build_posts.py --posts posts.json --date D --repo <リポジトリ>
   - NG が出たら直してやり直す。数字の NG は、号の解説を読み直して、無い数字なら消す
5. git add data/posts → コミット「投稿下書き D」→ push（--force はしない）
6. 約90秒後に https://ai-choukan.vercel.app/data/posts/D.json が読めるかを確かめる
7. 報告：main の見出し、others の見出し、夜の1本の話題、note の字数、X の本数、画像の枚数

## 7. 投稿の手順（高崎さんから「AI朝刊の投稿をお願いします（D号）」と来たとき）

依頼文が、その日の投稿への了承になる。了承は D 号の下書きの分だけ。別の日の分や、下書きにない内容は投稿しない。
入力はすべて Claude が行う。高崎さんにコピーや貼り付けを頼まない。

### 7-0. 準備
- ブラウザは Claude in Chrome（CIC）を使う。スキル chrome-browser・note-editor-ops・cic-login-handoff を読む
- リポジトリを add_repo（owner taka-a1111、repo ai-choukan、access push）で取り、data/posts/D.json を読む。posted に note_url があれば投稿済みなので、二重に投稿せず、そう伝える
- アカウントを確かめる。note は https://note.com/api/v2/current_user の urlname が infosuccess_jp。違えば何も入力せず、cic-login-handoff の形で切り替えを頼む（note は同時に1つしかログインできない）
- X は左下の表示が @infosuccess_jp か。同じ Chrome でナンパ部（@nampabu）なども使うため、別のアカウントになっていることが多い。左下 [data-testid="SideNav_AccountSwitcher_Button"] を押し、出てきた一覧の @infosuccess_jp を押して切り替える（パスワードは要らない）。一覧に @infosuccess_jp が無いときは何も入力せず、cic-login-handoff の形で頼む。投稿が終わったら、元のアカウントに切り替えて戻す
- PC・Chrome につながらないときは、入力せずに「PCのChromeを開いてから、もう一度送ってください」と伝える

### 7-1. 直したい点があるとき
依頼文に「直したい点」があれば、先に posts.json を直して tools/build_posts.py で組み立て直し、push する（第6章）。事実を足す直しは、号の解説にあるものだけ。直した文面を高崎さんに見せ、「これで投稿します」と伝えてから先へ進む（返事は待たなくてよい。直しの中身が依頼とずれそうなときだけ確かめる）。

### 7-2. note
1. python3 tools/note_html.py --date D --repo <リポジトリ> --out note_payload.json で、タイトルと本文のHTMLを作る
2. 同じタイトルの下書きがすでにあれば（https://note.com/api/v2/creators/infosuccess_jp/contents?kind=note や下書き一覧で確かめる）、新しく作らずにそれを開く。無ければ https://note.com/notes/new を開く
3. タイトルは textarea（記事タイトル）に value の setter と input イベントで入れる。本文は .ProseMirror の全体を選択し、text/html の paste イベントで入れる（note-editor-ops 第4章）
4. 入れたあと、.ProseMirror の子要素の並び（H2,UL,P…）が note_payload.json の blocks と同じかを確かめる
5. 画像：7-6 のとおり ChatGPT で作って入れる（見出し画像、「## 概要」の下の図、「## 今日やること3つ」の下の図）。本文を入れ終えてから行う
6. 「下書き保存」→「公開に進む」。ハッシュタグは「AI」「AIニュース」と、話題に合うものを1〜2個（例：ChatGPT、SEO）。記事タイプは無料
7. 「投稿する」を押す。安全機能で押せないときだけ、cic-login-handoff の形で高崎さんに押してもらう
8. 公開ページ https://note.com/infosuccess_jp/n/（key）を開き、タイトル・見出し・出典のリンクが出ているかを確かめる

### 7-3. X
1. 朝の1本：文の末尾に、改行して note の公開URLを足す（URLは23字として数える。全角140字相当を超えるなら、最後の1文を短くする）。https://x.com/compose/post で本文を text/plain の paste で入れ、見出し画像を添付して（7-6）、すぐ投稿する（note-editor-ops 第8章）
2. 夜の1本と今日の3つ：下書きの at の時刻（19:00・21:00）の予約投稿にする。今日の3つは末尾に note のURLを足す（画像は付けない。note のリンクのカードが出る）。夜の1本は文を足さず、xfig の図を添付する（7-6）。https://x.com/compose/post/unsent/scheduled で日時と本文を確かめる
   - at の時刻をもう過ぎているときは、前の投稿から3分以上あけてすぐ投稿する
   - 予約ができないときも、3分以上あけてすぐ投稿し、報告に書く
3. 投稿した分のURLと、予約にした分の時刻を控える
4. x が2本だけの古い下書き（1本目・今日の3つ）は、1本目をすぐ、今日の3つを19:00の予約にする

### 7-3b. Facebook（インフォサクセスのページ）
- ページ：https://www.facebook.com/61596721610257 （2026-11-12 作成。高崎さんの個人アカウントが管理）
- 投稿する文面：X の朝の1本と同じ文の末尾に、改行して note の公開URLを足す（リンクのカードに note の見出し画像が出るので、画像は付けない）
- 手順
  1. ページを開き、左の「切り替える」→「切り替える」でページとして操作する状態にする（「新しいページへようこそ」が出たら「ページを使用」）
  2. 「その気持ち、シェアしよう」を押し、出てきた入力欄 [contenteditable="true"][role="textbox"] に text/plain の paste で文面を入れる。数秒待つとリンクのカードが出る
  3. 「次へ」→ 投稿設定の画面で「投稿」を押す
  4. ページを開き直し、投稿が出ていることを確かめる
  5. 右上のアカウント →「高崎 信吾に切り替える」で個人のプロフィールに戻す（同じ Facebook を、きょうのあそび研究所など別の案件でも使うため）
- 安全機能で「投稿」が押せないときは、そこで止めて知らせる（note・X の投稿は止めない）

### 7-4. 記録と報告
1. python3 tools/mark_posted.py --date D --repo <リポジトリ> --note-url <URL> --x-url <投稿した分のURL>（投稿した本数だけ）。予約にした分は、data/posts/D.json の posted に "x_scheduled": ["19:00","21:00"] のように時刻を足す
2. Facebook に出したら、data/posts/D.json の posted に "facebook": true を足す
3. git add data/posts → コミット「投稿済み D」→ push
4. 高崎さんに短く報告：note のURL、X の投稿した分のURLと予約の時刻、Facebook に出したか（URLは1行に単独で）、直した点があればその内容

### 7-5. 途中で止まったとき
どこまで終わったか（noteは下書きまで、Xは未投稿 など）と、止まった理由をそのまま伝える。投稿できた分は mark_posted.py で記録しておく（次に頼まれたとき、二重に投稿しないため）。

### 7-6. 画像（ChatGPT で作り、クリップボードで渡す）

画像のデータは、ダウンロードフォルダもコンテナも通さない。ChatGPT のタブでクリップボードに写し、note・X のタブで本物の ctrl+v で受け取る（Claude の会話に画像のデータが入らない）。補助関数は tools/browser_helpers.js（ページを開くたびに、該当部分を javascript_tool で実行して定義する）。

作る順番と間隔
- 生成はスキル chatgpt-image-pacing に従う（共有ログ imggen_log に run_chatgpt_ai-choukan_D-eyecatch のように記録、いまの間隔、他の会話との順番、制限が出たら止まる）。最初の1枚の前に、ログで間隔と制限を確かめる
- 1日4枚：eyecatch → fig1 → fig2 → xfig。1枚ごとに https://chatgpt.com/ を開き直して新しいチャットで送る（通常の「Chat」モード。__mode() が true）
- 指示文は python3 tools/img_prompt.py --date D --repo <リポジトリ> --which <eyecatch|fig1|fig2|xfig> --json で作り、__send(指示文) で送る（'SENT' 以外なら送らずに止める）

1枚の流れ
1. ChatGPT：__state() を30秒ごとに見て、n が1以上かつ stop が false になるまで待つ（最大5分。__bad() に何か出たら制限として扱う）
2. 仕上がりを1回だけ見る：最後の画像を scrollIntoView してスクリーンショット（小さいときは zoom で拡大）。文言が指示文と1字ずつ合っているか、文字が帯や箱からはみ出したり重なって欠けたりしていないか、余計な文字・数字・人物・ロゴ・ほかの色が無いか、見出し画像の左下が空いているか。直すときは作り直さず「この画像をベースに、下記だけ修正してください」と直す箇所だけ頼む（1枚につき1回まで。直しも1回の生成として数える）。2回目もだめなら、その画像は使わない
3. ChatGPT のタブで __copy()（'COPIED' が返ること）
4. note のタブ：__sinkOn() → computer の key "ctrl+v" → __sinkGet() → __fit(window.__got, 幅, 高さ, ファイル名)
   - 見出し画像は 1280×670、図解は 1200×800
   - 見出し画像は、続けて __brand(ファイル) で左下に本物のロゴマークと「インフォサクセス」を描き足す（ChatGPT には社名もロゴも描かせず、左下を空けさせている）
5. note の見出し画像：エディタ上の画像ボタン →「画像をアップロード」を押す前に __capture()、押したら __setFile(null, ファイル) → 切り抜きの画面で「保存」
6. note の本文の図：__placeAfter('概要') で見出しの直後に空の段落を作ってカーソルを置き、__capture() → button[aria-label="メニューを開く"] →「画像」→ __setFile(null, ファイル)。入ったら __dropEmptyBefore('概要') で見出しと図の間の空の段落を消す（補助関数は tools/browser_helpers.js の TARGET 部分。__placeAfter・__dropEmptyBefore も同じファイル）
7. X：投稿画面の入力欄 [data-testid="tweetTextarea_0"] にフォーカスして、本物の ctrl+v を押すと画像が添付される。[data-testid="attachments"] が出たことを確かめる
   - 朝の1本の見出し画像は、ロゴ入りのものを付ける。note のタブで __toClip(ロゴ入りのファイル) をしてから、X のタブで ctrl+v する
   - 夜の1本の図（xfig）は、ChatGPT のタブで __copy() したものをそのまま ctrl+v でよい
8. ログを done_ にする

うまくいかないとき（投稿は止めない）
- 見出し画像が作れない：PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers python3 tools/note_eyecatch.py --date D --repo <リポジトリ> --out eyecatch_D.png で作った紺色の画像を、/mnt/user-data/uploads/ に写して file_upload で入れる。X の朝の1本は画像なしで出す
- 図解が作れない：その図は入れずに進める（本文は図が無くても読める）。xfig が作れなければ、夜の1本は画像なしで予約する
- 制限（Too many requests など）が出た：chatgpt-image-pacing のとおり limit_ を作り、残りの画像は作らずに、画像なしで投稿を続ける
- クリップボードに写せない（COPY_NG）：ChatGPT のタブを computer の screenshot で前面に出してから、もう1回だけ __copy()。だめならその画像は使わない
- 報告に、作れなかった画像と理由を書く

## 8. 自動投稿（毎朝の予約実行「AI朝刊の自動投稿（note・X）」）

高崎さんの決定（2026-11-11）：毎日、朝に note と X の朝の1本、夜に X を2本（19:00 に夜の1本、21:00 に今日の3つ）自動で出す。2026-11-12 から、朝に Facebook ページへも note を紹介する（7-3b）。予約実行そのものが、その日の投稿への了承になる。本人は見ていないので質問しない。

### 8-1. 投稿する前に確かめること（1つでも外れたら投稿しない）
- 日付 D は TZ=Asia/Tokyo date +%F で取る
- data/posts/D.json が無い：下書きが出ていない。投稿せず、通知して終わる
- posted.note_url がある：投稿済み。何もせず終わる
- "hold": true がある：高崎さんが止めた日。投稿せず、通知して終わる
- PC の Chrome（Claude in Chrome）につながらない：投稿せず、「AI朝刊の投稿：PCのChromeにつながらず投稿できませんでした。アプリのボタンから頼めば出せます」と通知して終わる
- note のアカウントが infosuccess_jp でない：何も入力せず、通知して終わる。X は 7-0 のとおり @infosuccess_jp に切り替えてから進み、終わったら元に戻す

### 8-2. 投稿
1. note：7-2 のとおり（新しい記事を作り、本文・ChatGPT の画像3枚（7-6）・ハッシュタグを入れて公開し、公開ページを確かめる）。画像に時間がかかるので、全体で20〜30分を見込む
2. X：7-3 のとおり（朝の1本はロゴ入りの見出し画像つきですぐ投稿、夜の1本は図つきで19:00、今日の3つは21:00の予約投稿）
3. Facebook：7-3b のとおり（ページに切り替えて note を紹介し、個人に戻す）
4. 記録：7-4 の 1〜3 のとおり（朝の1本のURL、予約の時刻、Facebook に出したか）。コミットは「投稿済み D」
5. 報告：SendUserMessage で note のURL、X の朝の1本のURL、予約の時刻、Facebook に出したか（URLは1行に単独で）。PushNotification は一行「AI朝刊の投稿：note・X・Facebook に出しました（X の夜は19:00と21:00）」

### 8-3. 止める・直す（高崎さんから、投稿の前に連絡が来たとき）
- 「今日は止めて」：data/posts/D.json に "hold": true を足して push する。出すと決めたら hold を消し、第7章の手順で投稿する
- 「ここを直して」：7-1 のとおり下書きを直して push する。自動投稿は直した下書きを使う
- 予約済みの X の夜の分を止める・直す：https://x.com/compose/post/unsent/scheduled で消す・直す

### 8-4. 途中で止まったとき
7-5 と同じ。投稿できた分は必ず記録し、どこまで終わったかと理由を SendUserMessage と PushNotification で知らせる。安全機能で公開のボタンが押せないときは、下書き保存までで止め、そう知らせる（アプリのボタンから頼めば続きができる）。
