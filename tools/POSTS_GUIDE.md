# 投稿下書きの書き方と投稿の手順（note・X） ver1.4 (2026-11-11)

AIトレンド朝刊のその日の号から、note と X の下書きを作るときの決まり。
下書きはアプリの「投稿」タブに出る。毎朝の予約実行「AI朝刊の自動投稿（note・X）」が、その日の下書きを note と X に投稿する（第8章）。
自動で出なかった日は、高崎さんがアプリの「Claudeに投稿を頼む」を押し、開いたプロジェクト「AI朝刊」のチャットに依頼文を貼り付けて送ると、Claude が投稿する（第7章）。
自動投稿の予約実行と高崎さんの依頼の、どちらでもない投稿はしない。

## 1. だれに向けて書くか

- 読者：Web担当者、小さな会社の経営者、フリーランス
- 扱う話：SEO・AI検索、集客、サイト制作、業務の自動化、AIの導入に効く話だけ
- 書き手：インフォサクセス（SEO・Web制作・自動化・AI導入の支援をしている立場）
- ねらい：ニュースを並べるのではなく、「で、何をすればいいか」まで書く

## 2. 話題の選び方

- 今日の1本（main）：読者の仕事に一番効く話題を1つ
  - 「業務に効く」の印（biz）があり、重要度が高く、読者が自分で手を動かせるものを優先する
  - 新モデルの性能比較、企業の買収・株価、研究の話は、読者の行動が変わらないかぎり選ばない
  - 前の日の main と同じ出来事は選ばない（data/posts/ の直近3日分を見る）。続報は、読者のやることが変わるときだけ
- ほか3本（others）：読者に関係のある話題を3つ。main と似た話に寄せず、分野を散らす
- 読者に効く話題が1つもない日は、活用ノウハウや国内の事例から選ぶ。それも無ければ下書きを作らず、報告に書く

## 3. note の型

タイトル：何が起きたか＋読者に何の関係があるか。60字まで。あおらない（「衝撃」「ヤバい」「知らないと損」などは使わない）

本文（見出しは行頭に ## 。この順番で書く）

1. ## 30秒まとめ　3行の箇条書き。3行目は「日本で使えるか・いつからか」
2. ## 概要　号の解説をもとに、やさしい言葉で。図解がある話題は、その中身を箇条書きにする（note は表が使えない）
3. ## いつ・誰が使える？　号の avail のとおり。分からないことは「発表されていません」と書く
4. ## 小さな会社への影響（私の見立て）　事実ではなく見立てだと分かる書き方で、2〜4文
5. ## 今日やること3つ　番号つき。今日できる具体的な作業。1つは「いまの状態を記録する」など、道具なしでできること
6. ## ほかに押さえておきたい3本　各2〜3文。見出し1行＋何が起きたか＋読者への意味
7. ## 出典　main と others の出典のURLを、1行に1つ。前後に文字を付けない
8. 最後に相談窓口への1文（毎回同じ）
   「AIを仕事にどう入れるか、検索やAIからの集客をどう整えるかのご相談は、プロフィールの窓口からどうぞ。」

長さ：1200〜2200字

## 4. X の型

- 2本作る
  - 1本目：main を3つの箇条書きで。最後に「くわしくは note に」の1文（URLは入れない。投稿のときに Claude が note のURLを足す）
  - 2本目：「今日のAIニュース、Web担当者向けに3つだけ。」で始め、main と others から3つを番号つきで
- 全角140字まで（tools/build_posts.py が数える）
- ハッシュタグは付けない。絵文字は使わない

## 5. 事実の扱い（必ず守る）

- 書いてよい事実は、その日の号の、選んだ話題の解説（lead・points・avail・why・図解・出典の要約）にあることだけ
- 数字・固有名詞・日付を足さない。号にない出典のURLを書かない
- 分からないことを分かったように書かない
- 「私の見立て」と「今日やること」は書き手の考えなので、事実のように言い切らない（「〜と見ています」「〜しておくと安心です」）
- 出典の文をそのまま写さない。自分の言葉で書く
- 取引先の名前や案件の話を入れない
- 太字記号（**）を使わない

## 6. 作る手順

1. その日の号（data/issues/D.json）があるかを確かめる。無ければ作らずに知らせる
2. data/posts/ の直近3日分を見て、同じ話題を続けて選ばないようにする
3. 話題を選び、posts.json を書く（形は tools/build_posts.py の先頭）
4. python3 tools/build_posts.py --posts posts.json --date D --repo <リポジトリ>
   - NG が出たら直してやり直す。数字の NG は、号の解説を読み直して、無い数字なら消す
5. git add data/posts → コミット「投稿下書き D」→ push（--force はしない）
6. 約90秒後に https://ai-choukan.vercel.app/data/posts/D.json が読めるかを確かめる
7. 報告：main の見出し、others の見出し、note の字数、X の本数

## 7. 投稿の手順（高崎さんから「AI朝刊の投稿をお願いします（D号）」と来たとき）

依頼文が、その日の投稿への了承になる。了承は D 号の下書きの分だけ。別の日の分や、下書きにない内容は投稿しない。
入力はすべて Claude が行う。高崎さんにコピーや貼り付けを頼まない。

### 7-0. 準備
- ブラウザは Claude in Chrome（CIC）を使う。スキル chrome-browser・note-editor-ops・cic-login-handoff を読む
- リポジトリを add_repo（owner taka-a1111、repo ai-choukan、access push）で取り、data/posts/D.json を読む。posted に note_url があれば投稿済みなので、二重に投稿せず、そう伝える
- アカウントを確かめる。note は https://note.com/api/v2/current_user の urlname が infosuccess_jp、X は左下の表示が @infosuccess_jp。ナンパ部など別のアカウントだったら何も入力せず、cic-login-handoff の形で切り替えを頼む
- PC・Chrome につながらないときは、入力せずに「PCのChromeを開いてから、もう一度送ってください」と伝える

### 7-1. 直したい点があるとき
依頼文に「直したい点」があれば、先に posts.json を直して tools/build_posts.py で組み立て直し、push する（第6章）。事実を足す直しは、号の解説にあるものだけ。直した文面を高崎さんに見せ、「これで投稿します」と伝えてから先へ進む（返事は待たなくてよい。直しの中身が依頼とずれそうなときだけ確かめる）。

### 7-2. note
1. python3 tools/note_html.py --date D --repo <リポジトリ> --out note_payload.json で、タイトルと本文のHTMLを作る
2. 同じタイトルの下書きがすでにあれば（https://note.com/api/v2/creators/infosuccess_jp/contents?kind=note や下書き一覧で確かめる）、新しく作らずにそれを開く。無ければ https://note.com/notes/new を開く
3. タイトルは textarea（記事タイトル）に value の setter と input イベントで入れる。本文は .ProseMirror の全体を選択し、text/html の paste イベントで入れる（note-editor-ops 第4章）
4. 入れたあと、.ProseMirror の子要素の並び（H2,UL,P…）が note_payload.json の blocks と同じかを確かめる
5. 見出し画像：PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers python3 tools/note_eyecatch.py --date D --repo <リポジトリ> --out eyecatch_D.png で作る（紺色 #00243F の地に記事タイトルとロゴマーク、1280×670）。作った画像を必ず開いて見て、文字のはみ出しや重なりが無いことを確かめてから、/mnt/user-data/uploads/ に写し、見出し画像のボタン →「画像をアップロード」→ file_upload →「保存」で入れる（note-editor-ops 第5章）
6. 「下書き保存」→「公開に進む」。ハッシュタグは「AI」「AIニュース」と、話題に合うものを1〜2個（例：ChatGPT、SEO）。記事タイプは無料
7. 「投稿する」を押す。安全機能で押せないときだけ、cic-login-handoff の形で高崎さんに押してもらう
8. 公開ページ https://note.com/infosuccess_jp/n/（key）を開き、タイトル・見出し・出典のリンクが出ているかを確かめる

### 7-3. X
1. 1本目の文の末尾に、改行して note の公開URLを足す（URLは23字として数える。全角140字相当を超えるなら、最後の1文を短くする）
2. https://x.com/compose/post で本文を text/plain の paste で入れ、投稿する（note-editor-ops 第8章）
3. 2本目（今日の3つ）は、1本目のあと3分以上あけて投稿する。末尾に note のURLを足す
4. 投稿した2本のURLを控える

### 7-4. 記録と報告
1. python3 tools/mark_posted.py --date D --repo <リポジトリ> --note-url <URL> --x-url <1本目> --x-url <2本目>
2. git add data/posts → コミット「投稿済み D」→ push
3. 高崎さんに短く報告：note のURL、X の2本のURL（URLは1行に単独で）、直した点があればその内容

### 7-5. 途中で止まったとき
どこまで終わったか（noteは下書きまで、Xは未投稿 など）と、止まった理由をそのまま伝える。投稿できた分は mark_posted.py で記録しておく（次に頼まれたとき、二重に投稿しないため）。

## 8. 自動投稿（毎朝の予約実行「AI朝刊の自動投稿（note・X）」）

高崎さんの決定（2026-11-11）：毎日、朝に note と X の1本目、夜19:00に X の2本目を自動で出す。予約実行そのものが、その日の投稿への了承になる。本人は見ていないので質問しない。

### 8-1. 投稿する前に確かめること（1つでも外れたら投稿しない）
- 日付 D は TZ=Asia/Tokyo date +%F で取る
- data/posts/D.json が無い：下書きが出ていない。投稿せず、通知して終わる
- posted.note_url がある：投稿済み。何もせず終わる
- "hold": true がある：高崎さんが止めた日。投稿せず、通知して終わる
- PC の Chrome（Claude in Chrome）につながらない：投稿せず、「AI朝刊の投稿：PCのChromeにつながらず投稿できませんでした。アプリのボタンから頼めば出せます」と通知して終わる
- アカウントが infosuccess_jp でない（note・X のどちらか）：何も入力せず、通知して終わる

### 8-2. 投稿
1. note：7-2 のとおり（新しい記事を作り、本文・見出し画像・ハッシュタグを入れて公開し、公開ページを確かめる）
2. X の1本目：7-3 の 1〜2 のとおり、すぐ投稿する
3. X の2本目：その日の 19:00（日本時間）の予約投稿にする（note-editor-ops 第8章「予約投稿」。末尾に note のURLを足す）。https://x.com/compose/post/unsent/scheduled で日時と本文を確かめる。予約ができないときは、1本目から3分以上あけてすぐ投稿し、報告に書く
4. 記録：mark_posted.py に note のURLと X の1本目のURLを渡す。2本目を予約にした日は、data/posts/D.json の posted に "x2_scheduled": "19:00" を足す → コミット「投稿済み D」→ push
5. 報告：SendUserMessage で note のURL、X の1本目のURL、2本目の予約時刻（URLは1行に単独で）。PushNotification は一行「AI朝刊の投稿：note と X に出しました（2本目は19:00）」

### 8-3. 止める・直す（高崎さんから、投稿の前に連絡が来たとき）
- 「今日は止めて」：data/posts/D.json に "hold": true を足して push する。出すと決めたら hold を消し、第7章の手順で投稿する
- 「ここを直して」：7-1 のとおり下書きを直して push する。自動投稿は直した下書きを使う
- 予約済みの X の2本目を止める・直す：https://x.com/compose/post/unsent/scheduled で消す・直す

### 8-4. 途中で止まったとき
7-5 と同じ。投稿できた分は必ず記録し、どこまで終わったかと理由を SendUserMessage と PushNotification で知らせる。安全機能で公開のボタンが押せないときは、下書き保存までで止め、そう知らせる（アプリのボタンから頼めば続きができる）。
